# 정보의 3단계 — 공식 · 계산/통계 · 여론/커뮤니티

Game Hub의 **핵심 정보 철학**입니다. 모든 게임, 모든 레코드에 적용합니다.

> 사용자가 무엇을 찾든 한 곳에서 순서대로 확인할 수 있게 한다.
> ① 게임사가 공식적으로 뭐라고 했는지 → ② 그걸 계산하면 실제로 어떤 결과가 나오는지 → ③ 유저들은 그걸 어떻게 받아들이는지

세 단계는 태그가 아니라 **저장 위치·검증 규칙·화면이 모두 다른 별개의 계층**입니다. 한 레코드에 두 단계를 섞지 않습니다.

| 단계 | 무엇 | 예 (명조) | 표현 방식 |
|---|---|---|---|
| **1. 공식** `official` | 게임사·공식 채널이 직접 준 원자료 | 스킬 설명·배율, 공명 체인 효과, 픽업 기간, 리딤 코드, 튜닝 확률 | 사실로 서술 |
| **2. 계산/통계** `analysis` | 공식 데이터로 계산·집계한 비교적 객관적인 결과 | 돌파 효율, 무기 효율, 버전별 획득 별의 소리, 기대 뽑기 수, 복각 간격 | **"이 조건에서 약 …"** — 조건과 함께만 |
| **3. 여론/커뮤니티** `community` | 커뮤니티에서 실제로 형성된 의견의 요약 | 1돌 vs 전무 여론, 조합 평가, 사용감, 스토리 평가, 꿀팁 | **"…라는 의견이 많다"** — 사실처럼 쓰지 않음 |

같은 주제를 세 단계로 나누면 이렇습니다.

```
공식      1체인: 크리티컬 16% 증가 …                           ← resonators/cheongcho#chain-1
  ↓
계산      에코 제외 시 명함 41% → 1돌 57% (옥빛 구름 Lv.90 조건)  ← analysis/cheongcho-crit-budget
  ↓
커뮤니티  "메인 딜러는 전무 먼저"가 다수, 1돌은 고점·편의 평가…     ← community/cheongcho-investment
```

## 1. 공식

- 공식 홈페이지·공지·공식 SNS·인게임 문구(데이터 DB로 확인한 것 포함)만.
- **요약한다. 원문을 통째로 옮기지 않는다.** 스킬 툴팁 전문 대신 핵심 효과 1~3문장 + 핵심 수치(`values`).
- 공식 확률은 공식. 그 확률로 계산한 기대값은 계산 단계.
- 복각 주기로 "다음 복각"을 예상하는 것은 공식이 아니다(예측은 커뮤니티 의견으로만 다룬다).
- 저장: `news`, `schedule`, `database`, `version`, `codes` 모듈. 엔티티의 하위 항목(스킬, 체인, 패시브)은 `topics`.

## 2. 계산 / 통계

- 결과는 **계산 조건(`assumptions`)과 방법(`method`) 없이 존재할 수 없다** — 스키마가 강제.
- 절대값처럼 쓰지 않는다. ✗ "1돌은 18.3% 강해진다" → ✓ "이 조건에서는 약 18.3% 증가".
- 출처 없는 딜 수치를 옮기지 않는다. 공식 수치만으로 할 수 있는 계산은 Game Hub가 직접 하고 `method`에 "Game Hub 자체 계산"과 식을 적는다.
- **유저가 실제로 묻는 질문에 답한다.** 캐릭터라면 첫 계산은 "1돌 vs 명전(명함+전무), 뭐가 더 좋나"처럼 투자 결정에 대한 결론이다(`kind: breakpoint`가 맨 위에 정렬).
  단순 기록성 숫자(픽업 경과일 등)는 넣지 않는다.
- **돌파 단계별 변화는 그래프로.** `chart`에 명함=기준, 1~6돌 딜을 넣으면 결론 바로 아래 막대 그래프(명함 대비 +%)가 그려진다.
- 저장: `analysis` 모듈 (`AnalysisRecord`).

## 3. 여론 / 커뮤니티

- 실제 커뮤니티 글(본문·댓글)을 **직접 읽고, 반복해서 보이는 의견만** 요약한다. **AI가 스스로 평가를 만들지 않는다.**
- 사실처럼 쓰지 않는다. ✗ "이 캐릭터는 2돌이 필수다" → ✓ "2돌을 핵심으로 보는 의견이 많이 보인다".
- 결론만 쓰지 않고 **왜** 그런 평가인지 쓴다. 의견이 갈리면 숨기지 않고 `divided`에 양쪽 이유를 적는다.
- 한 커뮤니티의 의견을 전체 여론처럼 쓰지 않는다. 요약문에 어느 커뮤니티 기준인지 밝히고, 화면은 출처 커뮤니티가 1곳이면 자동으로 경고를 띄운다.
- 모든 게임 외적인 사건·잡담을 모으지 않는다. 플레이 판단에 도움이 되는 것(평가, 돌파/무기 여론, 조합, 사용감, 스토리·버전 평가, 팁, 자주 하는 실수, 논쟁)만 **집대성해 짧게**.
- `consensus`(strong/moderate/mixed/weak)는 점수가 아니라 "의견이 얼마나 일치하는가"의 설명이다.
- **평가 항목을 먼저, 한 줄로.** 사용감 같은 인상 나열이 아니라 판단 기준을 `verdicts`로 명시한다. 캐릭터라면 최소:
  티어 · 파티 순위 · 전용 무기 의존도(필수/대체 가능) · 파티 의존도 · 돌파 가치 — `kind: evaluation` 레코드에.
  투자 결론(1돌 vs 명전, 투자 순서)은 `kind: investment`, 조합은 `kind: team`.
- **여러 커뮤니티를 본다.** 국내(디시·아카라이브) + 해외(Reddit) + YouTube + 티어·계산 사이트(Prydwen 등). 한 곳만 본 요약은 만들지 않는다.
- **의견 문장마다 출처를 달지 않는다.** 출처는 카드 맨 아래 한 곳(`sources`)에 모은다.
- **출시 당시와 지금을 구분한다.** 티어 조정·파츠 출시·메타 변화로 평가가 **크게** 바뀌었을 때만 `shift`(출시 당시 → 현재 + 이유)에 적는다. 현재 평가가 `verdicts`, 과거는 `shift`.
  근거: 티어 사이트 변경 기록(Prydwen changelog), 버전별 설문(아카 성능 만족도), 날짜가 다른 글.
- **커뮤니티 탭 = 최근 핫이슈 + 꿀팁.** 게임 내(버전·복각·과금 이벤트)와 게임 외(오프라인 행사·사건사고·결제) 이슈를 `kind: issue` + `scope`로, 유저가 인정한 팁은 `kind: tip`으로. `background`에 무슨 일인지 한 줄, `summary`에 여론 결론.
  캐릭터·무기 평가는 해당 엔티티 페이지에만 보인다.
- **버전별 스토리 평가**는 커뮤니티 탭 안의 독립 목록(버전·별점 → 상세 링크). 상세는 흐름 → 별점(근거) → 평가 요소 → 결론 → 국내/해외 반응 순.
  별점은 AI가 매기지 않는다 — 실제 설문 평균 등 근거가 있는 값만(`rating.basis`), 없으면 비운다("집계 전").
- 저장: `community` 모듈 (`CommunityRecord`).

## 연결 — `subjects`

계산·커뮤니티 레코드는 무엇에 대한 것인지 `subjects`로 공식 레코드를 가리킵니다.

```yaml
subjects: [resonators/cheongcho, resonators/cheongcho#chain-1, weapons/okbit-gureum]
```

- `<컬렉션>/<id>` 또는 `<컬렉션>/<id>#<topic id>`. 검증기가 대상 레코드·토픽이 실제로 있는지 확인한다.
- 공식 페이지는 자신을 가리키는 계산·커뮤니티를 자동으로 모아 **공식 → 계산 → 커뮤니티** 순서로 보여준다. 토픽(예: 1체인) 아래에는 그 토픽에 대한 계산·여론 한 줄이 바로 붙는다.
- 엔티티(공명자·무기…)에 연결된 계산·커뮤니티는 **그 엔티티 페이지에만** 보인다. 계산·커뮤니티 탭에는 어디에도 속하지 않는 것(가챠 통계 등)만 남고, 비면 탭을 숨긴다.
- 계산·커뮤니티 페이지는 거꾸로 "다루는 공식 정보"를 링크한다.
- 버전 페이지는 버전 기간(또는 레코드의 `version`)에 속한 공식 일정·코드·공지·출시/복각을 모으고, 그 버전을 `subjects`로 가리키는 계산·여론을 붙인다.

## 신선도 — 기준 버전과 상태

패치로 정보가 빨리 낡습니다. 삭제하지 않고 표시합니다.

| 필드 | 뜻 |
|---|---|
| `version` | 기준 게임 버전. 계산·커뮤니티는 필수 |
| `updatedAt` | 작성·계산·수정일 |
| 마지막 확인 | 출처의 `verifiedAt`/`collectedAt` 중 가장 최근 (자동) |
| `status` | `current`(기본) · `outdated`(전제가 바뀜, 경고 표시) · `archived`(기록용) |

`version`이 현재 버전보다 낮으면 화면에 "3.6 버전 기준 · 현재 3.7에서 다시 확인되지 않음"이 자동으로 붙습니다.

## 화면 규칙 (모든 게임 공통 — 공통 컴포넌트와 검증기에 구현되어 있어 새 게임도 자동 적용)

- 단계는 **텍스트 배지**로 표시한다(색만으로 구분하지 않음): <kbd>공식</kbd> 녹색 · <kbd>계산</kbd> 보라 · <kbd>커뮤니티</kbd> 황토.
- 순서는 항상 공식 → 계산 → 커뮤니티. 단, 엔티티 페이지 맨 위 **한눈에 보기**에 핵심 판정을 모은다(각 줄에 단계 배지, 누르면 해당 카드로 이동).
  항목·순서는 `game.yaml` 모듈의 `glance`로 정한다. 명조 공명자: 티어 → 파티 순위(서포터는 역할) → 전용 무기 의존도 → 1돌 / 명전(계산 `answer`) → 조작 난이도.
- **두괄식.** 계산·평가는 결론 한 줄을 맨 위에 크게. 계산 과정·조건·표·세부 의견·근거는 "계산 과정 보기" / "자세한 의견 보기" 버튼 안에.
  → 계산 레코드의 `results[0]`, 커뮤니티 레코드의 `summary`가 그 결론이다. 짧게(1~2문장) 쓴다.
- **긴 공식 문구는 버튼 안에.** 스킬·체인·패시브 같은 토픽은 이름 한 줄만 보이고, 누르면 요약·수치가 펼쳐진다. 수치만 있는 토픽(능력치)은 바로 보인다.
- **안내 문구를 붙이지 않는다.** "사실이 아니라 여론입니다" 같은 면책 문장 대신 배지와 출처 커뮤니티 이름으로 충분하다.

## 절대 하지 말 것

1. 공식 효과와 계산 결과를 한 줄에 섞기 (✗ "1돌 효과: 공격력 +20%, 실질 DPS +17%")
2. 계산 결과를 조건 없이 절대값처럼 쓰기
3. 커뮤니티 의견을 사실처럼 쓰기
4. 커뮤니티에서 확인되지 않은 평가를 AI가 만들어 넣기
5. 원문을 요약 없이 통째로 붙여 넣기

## 다른 게임에 적용하기

최상위 개념(공식 / 계산 / 커뮤니티)은 모든 게임에서 같고, 그 안의 세부 항목은 게임마다 `game.yaml`로 정합니다.

- 공식: 게임에 맞는 `database` 모듈과 `fields`, 상세 페이지의 `sections`(스킬·체인·패시브·보스 패턴…)
- 계산: `analysis`의 `kind` — 돌파 효율, 무기 효율, 조합 딜, 스탯 효율, 세팅 계산, 획득 재화, 이벤트 효율, 육성 비용, 파밍 효율, 가챠 통계
- 커뮤니티: `community`의 `kind` — 평가, 돌파·무기 여론, 조합, 사용감, 스토리, 버전 평가, 팁, 실수, 논쟁

예: 원신·스타레일은 명조와 거의 같은 구성, 명일방주는 `operators`(정예화·모듈), 메이플스토리는 `jobs`/`bosses` + 계산(보스 결정석 수익, 코어 강화 비용) + 커뮤니티(직업 평가, 패치 반응).
