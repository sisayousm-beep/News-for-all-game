# Architecture

## 목표와 제약

- 수십 개 게임, 게임마다 다른 정보 구조, AI가 반복적으로 저장소를 갱신.
- 사람이 매일 손대지 않는다 → 저장소 자체가 안전장치(스키마·검증·범위 제한)를 가져야 한다.
- 모바일 우선급 UX, 게임·데이터가 늘어도 가벼운 페이지.

## 선택한 구조: Git 저장소 = 데이터베이스, 정적 사이트 생성

```
games/**/*.yaml ──► core/schema.ts (zod) ──► core/load.ts (검증) ──► core/hub.ts (조회·집계) ──► pages / modules / components
     데이터              형식 정의              일관성 규칙             애플리케이션 계층               UI
```

| 결정 | 이유 |
|---|---|
| **Astro 정적 사이트** | 페이지마다 필요한 HTML만 생성, 클라이언트 JS 거의 없음 → 모바일에서 빠름. 서버 불필요, 어디든 배포 가능. |
| **YAML 파일, 레코드 1개 = 파일 1개** | AI가 한 항목만 정확히 고칠 수 있고, diff가 작아 리뷰·되돌리기 쉬움. 주석 가능. |
| **zod 스키마 한 곳(`schema.ts`)** | 빌드와 `npm run validate`가 같은 규칙을 사용 → "검증은 통과했는데 빌드 실패" 같은 불일치가 없음. |
| **Astro content collections 대신 자체 로더** | 컬렉션이 게임 설정에서 동적으로 정해지므로, 새 게임/모듈 추가 시 코드 수정이 필요 없도록. 로더는 Astro 없이도 동작해 스크립트·테스트에서 재사용. |
| **모듈 = 타입 + 설정** | `news`/`schedule`/`database` 타입을 코드로 구현하고, 게임은 `game.yaml`에서 조합·이름·필드를 정함. 명조 "공명자", 메이플 "직업", 명일방주 "오퍼레이터"는 모두 `database` 타입 + 다른 `fields`. |
| **출처 레지스트리** | 레코드는 등록된 출처 id로만 인용 → 출처 유형(신뢰도)이 일관되고, URL 도메인 검증 가능. |
| **업데이트 작업을 설정에 선언** | 작업 단위(게임×컬렉션)로 AI 컨텍스트·비용·오류 범위를 제한. |

## 디렉터리

| 경로 | 역할 |
|---|---|
| `games/<id>/game.yaml` | 게임 설정 (모듈, 출처, 업데이트 작업) |
| `games/<id>/<collection>/<record-id>.yaml` | 레코드 |
| `games/_template/` | 새 게임 템플릿 (`_`로 시작하는 폴더는 무시됨) |
| `src/core/schema.ts` | 모든 데이터 형식 (단일 진실 공급원) |
| `src/core/load.ts` | 파일 로딩 + 교차 검증 규칙 |
| `src/core/hub.ts` | 페이지용 API: 게임 조회, 전체 뉴스/일정/변경 집계, URL, 시간, 검색 인덱스 |
| `src/modules/<type>/` | 모듈 타입별 `List` / `Detail` / `Widget` 화면 |
| `src/modules/index.ts` | 타입 → 화면 매핑 |
| `src/pages/` | 라우팅. `games/[game]/[module]/[id]` 경로는 설정에서 자동 생성 |
| `src/i18n/ko.ts` | enum 값 표시 라벨 |
| `scripts/` | `validate`, `job-context`, `check-scope` |
| `tests/` | 검증 규칙 테스트 |

## 라우팅

| URL | 내용 |
|---|---|
| `/` | 대시보드: 게임 카드, 진행 중·예정 일정, 최신 소식, 최근 데이터 변경 |
| `/games/` | 게임 목록 |
| `/news/`, `/news/2/`… | 전체 게임 뉴스 (30개씩 페이지) |
| `/schedule/` | 전체 게임 일정 (진행 중/예정/최근 종료) |
| `/search/?q=` | 통합 검색 (`/search-index.json`을 검색 시에만 로드) |
| `/games/<game>/` | 게임 허브 개요: 모듈별 위젯 |
| `/games/<game>/<module>/` | 모듈 목록 화면 |
| `/games/<game>/<module>/<id>/` | 레코드 상세 |
| `/games/<game>/sources/` | 등록 출처·인용 수·업데이트 작업 |

## 시간

- 사이트는 한국어 우선이므로 날짜만 있는 값(`2026-09-17`)은 **KST 하루**로 해석, 표시도 KST.
- 시각이 있는 값은 반드시 오프셋 포함(`2026-09-17T10:00:00+09:00`) — 검증이 강제.
- 정적 페이지의 "진행 중/예정/종료"는 빌드 시 계산 + 브라우저에서 현재 시각으로 재계산(`Base.astro`) + 매일 자동 재빌드.

## 성능

- 페이지 단위 정적 HTML. 목록은 필요한 만큼만 렌더(대시보드 상위 N개, 뉴스 페이지네이션).
- 검색 인덱스는 검색 페이지에서만 lazy 로드. 레코드당 ~100B → 수만 건까지 단일 파일로 충분. 1MB를 넘으면 게임별 분할.
- DB 필터는 이미 렌더된 행을 숨기는 방식(추가 다운로드 없음). 한 모듈이 수천 행을 넘으면 페이지네이션 추가 필요.
- 이미지: `theme.icon`, 레코드 `image` 선택(`public/` 아래). 없으면 게임 색 타일·첫 글자 초상(외부 이미지 핫링크 없음). 모바일에서는 대체 타일을 숨겨 목록 밀도를 유지.
